# Project Status

**Project:** Instructor Copilot

**Current phase:** Phase 9B-B — Run Lifecycle + Timing Alignment

**Status:** READY FOR REVIEW

**Completed:**
- **Restart Session**: instructors can abandon the current rehearsal attempt and immediately start a clean run of the same Session at Step 1, without falsely completing it. `runController.restartRun()` terminalizes the old run (`termination: {kind: "restarted", at}`, never reusing its run id), persists it, then creates/persists a fresh `SessionRun` and repoints `active-run.json` at it — with partial-failure ordering designed so no failure can ever resurrect the abandoned run as live or leave the pointer/in-memory state referencing an unpersisted run (see `docs/architecture.md` → Run Lifecycle)
- **Discard Run**: instructors can abandon the current attempt and return to Training Detail without starting another run and without it counting as a completed session. `runController.discardRun()` persists the terminal run (`termination: {kind: "discarded", at}`) before clearing the active-run pointer, so the persisted terminal state stays authoritative even if pointer cleanup itself fails
- **Terminal run semantics**: `SessionRun.termination` (optional, additive — no schema-version bump) is mutually exclusive with `completedAt`; a terminated run has no open Step/pause interval, accepts no further checklist/evidence/note/navigation mutations (`assertMutable` in the run engine), and deliberately leaves its last-active `StepRun.status` as `"active"` as an honest record of where the instructor stopped rather than a fabricated completed Step. `isRunTerminal`/`isRunCompleted`/`isRunAbandoned` are the single source of truth used everywhere (Start Session guard, shutdown suspension, recovery) instead of duplicated `completedAt`/`termination` checks
- **Recovery/pointer handling**: a stale active-run pointer to a completed OR discarded/restarted run is cleared and silently ignored on startup — never offered for recovery, never surfaced as an error; `prepareRunForShutdown` treats any terminal run as a no-op (no new pause interval added to an abandoned run on quit)
- **Approved Step timing alignment**: Session 1 ES's 17 Step durations now match the approved instructional schedule exactly (1, 4, 2, 3, 2, 7, 4, 5, 5, 5, 4, 12, 8, 6, 5, 7, 5 = 85 minutes total), replacing the previous allocation that summed to 90 but diverged from the approved per-slide checkpoints documented in the Phase 9A audit
- **Explicit facilitation buffer**: new optional Session-level `facilitationBufferMinutes` field (additive, no schema-version bump; absent = 0). Session 1 ES declares `facilitationBufferMinutes: 5`, so its Step-plan sum (85) plus buffer (5) equals its `plannedDurationMinutes` (90) — validated by `validateSessionSemantics` only when a Session explicitly declares the field, so every Session authored before this phase is unaffected. The buffer is never a fake instructional Step; at the run level it is always derived from existing snapshots (`plannedDurationMinutesSnapshot` minus the sum of Step snapshots), not a new persisted run field
- **Buffer-aware live status**: Instructor Mode's live STATUS block now shows `MARGEN`/`BUFFER` (with remaining minutes) instead of `ATRASADO`/`BEHIND` once the instructor is on the Session's final Step, has passed its content checkpoint, but is still within the Session's full planned duration — every earlier Step's schedule-delta behavior is completely unchanged, so the buffer can never mask real lateness on Slides 1–16. On Slide 17 the side panel shows an explicit `MARGEN DE CIERRE: 5 min` note whenever a buffer is authored, replacing the old "the closing Step is just 10 minutes" framing
- **Completed-run total delta fix**: `completedRunScheduleDeltaMinutes` now compares actual active time against the Session's own planned total (e.g. 90) rather than merely the sum of Step plans (e.g. 85) — a Session completed in exactly 90 minutes now correctly reports a zero overall delta instead of appearing 5 minutes over; unaffected for any run with no buffer (Step-plan sum already equaled the Session plan)
- **Run Report**: gained `plannedBufferMinutes` (0 when none) and `bufferUsedMinutes` (capped at the planned buffer, distinct from an ordinary overrun which still shows in `deltaMinutes`); individual Step over/under status is untouched — a Step can run over its own local plan while the Session still finishes within its buffer, and the report shows both
- **Instructor Mode UI**: new "Session actions ▾" disclosure (status header, deliberately away from Next/Pause/Skip) exposing Restart Session / Discard Run, each behind an explicit `window.confirm` with Spanish/English text from the built-in dictionary; the recovery-banner dismiss action was relabeled "Ocultar"/"Dismiss" so it no longer collides with the Spanish word "Descartar" used for Discard Run
- Small approved content cleanup: Session 1 ES Slide 1's transition typo ("recojamos las primeras instintivas del grupo") corrected to "recojamos las primeras intuiciones del grupo"; Slide 17's facilitator guidance rewritten to describe the now-explicit 5-minute close / 5-minute buffer split
