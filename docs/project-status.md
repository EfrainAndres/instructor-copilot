# Project Status

**Project:** Instructor Copilot

**Current phase:** Phase 7 — Run Report

**Status:** READY FOR REVIEW

**Completed:**
- Phase 6 Evidence Staging + Active Run Recovery / clean-shutdown hardening (see prior entries) — approved and closed
- Instructor Notes:
  - Pure `addInstructorNote(run, session, {stepId, noteId, timestamp, text})` engine operation: rejects a completed run, requires the Step/StepRun to exist, requires a safe note id and non-blank trimmed text, appends one `InstructorNote`, and touches nothing else (timing/checklist/evidence/status unchanged) — allowed anytime before completion, including while paused
  - `validateSessionRunSemantics` now also enforces persisted-note invariants: unique note ids within the run, `runId`/`sessionId` consistency, `stepId` must exist among the run's own StepRuns, and `timestamp` must fall within `[startedAt, completedAt]` once the run is completed
  - Narrow main capability `run.addNote({text})`: the renderer sends only text; main generates the note id/timestamp and resolves the current active Step, using the existing mutation-guard/persist-then-commit pattern
  - Instructor Mode gained a compact per-Step Notes panel (textarea + Add Note, disabled while saving/blank; notes list oldest-to-newest with human-readable timestamps; textarea clears only on successful save); notes persist/recover exactly like the rest of `SessionRun` with no code changes needed to the Phase 6B recovery path
- Run Report (Phase 7's dedicated fifth MVP screen):
  - Pure, browser/Node-safe `buildRunReport(run: SessionRun)` in `session-engine/run/report.ts`: rejects an incomplete run, reads only `SessionRun`'s own historical snapshots/intervals/notes (never the live authored Session/Step, so a later Session edit can never rewrite a completed run's report), reuses the existing Phase-4 timing helpers (`stepActualDurationMinutes`, `sessionActiveElapsedMinutes`, `totalPausedMinutes`, `totalPlannedDurationMinutes`, `completedRunScheduleDeltaMinutes`) rather than introducing a second timing formula
  - Per-Step status: `on_time` / `over` / `under` (from `actual - planned`, normalized only for floating-point noise `< 1e-9`, no artificial "close enough" tolerance), `skipped` (StepRun's *final* status is `"skipped"` — a Step skipped and later revisited/finished reports its real timing instead), `not_reached` (final status still `"pending"` — the run completed before that Step was ever visited); Steps sorted by `stepOrderSnapshot`, notes grouped by `stepId` and sorted chronologically, all from copies (`SessionRun.stepRuns`/`notes` never mutated)
  - `RunReportScreen.tsx`: Session/run summary (started/completed/planned/actual/paused/overall delta as OVER/UNDER/ON TIME), a per-Step card list (order/title/type/status/planned/actual/delta, "—" for skipped/not-reached delta), and instructor notes grouped under their Step — imports `buildRunReport` from the leaf `session-engine/run/report` module (not the barrel) to keep Node fs/path/crypto code out of the renderer bundle
  - `App.tsx`: completing a run (`run.complete()` succeeding) transitions straight to the new `runReport` view using the already-returned `InstructorRunContext` — no reload from disk; "Back to Training" clears the run context and returns to the already-loaded Training bundle without touching the completed run file. `InstructorModeScreen`'s old completed-state block remains only as a small defensive fallback, not a duplicate report UI

**Current architecture:** `addInstructorNote` and `buildRunReport` live in `session-engine/run/` as pure, Electron-independent functions (report.ts has zero Node builtin imports, so it's directly importable in the renderer). `runController.addCurrentStepNote` follows the same current-Step-only, persist-then-commit pattern as `releaseCurrentEvidenceStage`. `RunReportScreen` is a new top-level screen alongside Home/TrainingDetail/SessionEditor/InstructorMode — not a subsection of Instructor Mode.
